## -------------Установка и использование-------------

### **Требования (Requirements):**

1. **Python** версии 3.14.3
2. **Poetry** версия 2.3.2
3. Смотрите файл `pyproject.toml` для получения информации о версиях зависимостях проекта.

### **Установка:**

1. **Клонируйте проект** с этого репозитория, используя в PyCharm (в командной строке терминала) команду:
```
git clone https://github.com/Dmitrii-dev-coder/backend_banking_widget.git
```
2. **Инициализируйте виртуальное окружение** командой:
```
python -m venv <название_окружения>
```
*Например:*
```
python -m venv venv
```
Однако важно убедиться, что у вас корректно настроен путь к Python в системной переменной `PATH`, чтобы команда работала без ошибок. О том, как добавить Python в PATH в Windows 11, смотри [здесь](https://ip-calculator.ru/blog/windows-11/how-to-add-python-to-path-on-windows-11-2/).
3. **Активируйте окружение** с помощью команды:
*   на macOS и Linux:
```
source venv/bin/activate
```
*   на Windows:
```
venv\Scripts\activate
```
*Или используйте `poetry shell` для активации виртуального окружения (доступно только при установленном плагине `poetry-plugin-shell`).*
4. **Установите все зависимости проекта** (указанные в файле `requirements.txt`) командой:
```
pip install -r requirements.txt
```
Также можно установить линтеры на выбор, используя Poetry с помощью команды:
```
poetry add --group lint <линтер>
```
Замените <линтер> на имя нужного линтера, например `flake8` или `mypy`, и они будут указаны в pyproject.toml. 
Если же использовать команду:
```
poetry add <линтер>
```
Тогда линтеры будут установлены для всего PyCharm

Проект имеет две точки входа:

1. **Основная программа (`main.py`):** Запуск через `python main.py` предоставляет пользовательский интерфейс для работы с банковскими транзакциями.

   ```
   Программа: Отсортировать операции по дате? Да/Нет да
   Программа: Отсортировать по возрастанию или по убыванию? по убыванию
   Программа: Выводить только рублевые транзакции? Да/Нет нет
   Программа: Отфильтровать список транзакций по определенному слову
   в описании? Да/Нет да
   Программа: Введите слово для поиска: Перевод организации
   Программа: Распечатываю итоговый список транзакций...
   Программа: Всего банковских операций в выборке: 33
   
   08.12.2019 Открытие вклада 
    Счет **4321
    Сумма: 40542 руб. 
    
    12.11.2019 Перевод с карты на карту
    MasterCard 7771 27** **** 3727 -> Visa Platinum 1293 38** **** 9203
    Сумма: 130 USD
    
    18.07.2018 Перевод организации 
    Visa Platinum 7492 65** **** 7202 -> Счет **0034
    Сумма: 8390 руб.
    
    03.06.2018 Перевод со счета на счет
    Счет **2935 -> Счет **4321
    Сумма: 8200 EUR
   
   Если выборка оказалась пустой, программа выводит сообщение:

    Программа: Не найдено ни одной транзакции, подходящей под ваши
    условия фильтрации
   ...
   ```

2. **Отладка и ручное тестирование (`debug.py`):** Запуск через `python debug.py` позволяет проверить каждую функцию из модулей `src/` по отдельности. Структура вывода разделена по модулям для удобства проверки:

   1. **Модуль masks.py:** Запуск функций get_mask_card_number и get_mask_account через обёртки run_mask_card_number и run_mask_account. Результатом будет:
   ```
   Замаскированный номер карты: 7000 79** **** 6361 Замаскированный номер счета: **4305
   ```

   2. **Модуль widget.py:** Запуск функции маскировки mask_account_card через run_mask_account_card и функции get_date через run_get_date. Результатом будет:
   ```
   Замаскированный объект: Счет **9589 Преобразованная дата: 11.03.2024
   ```

   3. **Модуль processing.py:** Запуск фильтрации filter_by_state и сортировки sort_by_date через обёртки run_filter_by_state и run_sort_by_date. Результатом будет отфильтрованный и отсортированный списки транзакций.

   4. **Модуль generators.py:** Запуск генераторов filter_by_currency, transaction_descriptions и card_number_generator. Результатом будет вывод отфильтрованных транзакций, описаний операций и сгенерированных номеров карт.

   5. **Модуль decorators.py:** Запуск декоратора log с записью в файл и выводом в консоль через обёртки run_log_to_file и run_log_to_console.

   6. **Модуль utils.py:** Запуск функции get_transactions_from_json_file через обёртку run_get_transactions_from_file. Результатом будет вывод списка словарей транзакций из файла data/operations.json.

   7. **Модуль external_api.py:** Запуск функции get_sum_of_transaction через обёртку run_get_sum_of_transaction. Результатом будет сумма транзакции в рублях, полученная через конвертацию.

   8. **Модуль readers.py:** Запуск функции get_transactions_from_csv_file через обёртку run_get_transactions_from_csv_file. Результатом будет список словарей транзакций из файла data/transactions.csv.

   9. **Модуль readers.py:** Запуск функции get_transactions_from_excel_file через обёртку run_get_transactions_from_excel_file. Результат будет список словарей транзакций из файла data/transactions_excel.xlsx.

   10. **Модуль search.py:** Запуск функций process_bank_search (поиск транзакций по строке в описании с использованием re) и process_bank_operations (подсчёт количества операций по категориям с использованием Counter). Результатом будет список найденных транзакций или словарь с количеством операций по каждой категории.

## -----------------------Тестирование------------------------

### Цель тестирования:
1. Тесты позволяют убедиться, что код работает так, как ожидалось, и выполняет все свои функции без ошибок.


2. Автоматизированные тесты предоставляют инструмент безопасности, позволяя разработчикам вносить изменения в 
   код без страха случайно что-то сломать.


3. Тесты ускоряют разработку за счет снижения количества времени, затрачиваемого на отладку и исправление ошибок в 
   будущем. Тесты также делают изменение и обновление кода более безопасными и предсказуемыми.


4. Регулярное тестирование помогает гарантировать, что изменения в одной части системы не нарушают функциональности в 
   других частях.


### Используемые инструменты: 
Для тестирования проекта используется библиотека **pytest**.

Все основные функции из модулей masks.py, widget.py, processing.py, generators.py, utils.py и external_api.py покрыты тестами. Тесты для новых модулей используют Mock и patch для изоляции работы с API и файловой системой.
Тесты находятся в папке `tests/`:
- `test_masks.py` — тесты маскировки номера карты и счёта;
- `test_widget.py` — тесты маскировки по типу (карта/счёт) и преобразования даты;
- `test_processing.py` — тесты фильтрации по статусу и сортировки по дате.
- `test_generators.py` - тесты: фильтрации транзакций по заданной валюте; возвращения корректных описаний для транзакций;
                           генерации правильных номеров карт в заданном диапазоне.
- `test_decorators.py` - тесты декоратора log: запись логов в файл и консоль; проверка формата времени; обработка исключений;
- `test_utils.py` — тесты чтения JSON-файла;
- `test_external_api.py` — тесты конвертации валюты с использованием Mock и patch;
- `test_search.py` — тесты функций поиска по описанию (process_bank_search) и подсчёта категорий (process_bank_operations).

### Покрытие тестами:

Все функции, в трех проверяемых модулях, покрыты тестами не менее чем на 80%,
что позволяет уверенно говорить о его надежности.

### Отчет о покрытии

HTML-отчет о покрытии тестами находиться в папке htmlcov/.
Чтобы сгенерировать отчет заново, запустите в терминале команду 
```
pytest --cov=src --cov-report=html
```

   **Тест 107:** Проверка функции, что при отсутствии данных в Excel-файле (пустая структура) она возвращает пустой список.
