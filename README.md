# =========Banking widget==========

## -------------Установка и использование-------------

### **Требования (Requirements):**

1. **Python** версии 3.14.3
2. **Poetry** версия 2.3.2
3. Смотрите файл `pyproject.toml` для получения информации о версиях зависимостях проекта.

### **Установка:**

1. **Клонируйте проект** с этого репозитория, используя в PyCharm (в командной строке терминала) команду:
```
git clone https://github.com/Dmitrii-dev-coder/backend_banking_widget.git
```
2. **Инициализируйте виртуальное окружение** командой:
```
python -m venv <название_окружения>
```
*Например:*
```
python -m venv venv
```
Однако важно убедиться, что у вас корректно настроен путь к Python в системной переменной `PATH`, чтобы команда работала без ошибок. О том, как добавить Python в PATH в Windows 11, смотри [здесь](https://ip-calculator.ru/blog/windows-11/how-to-add-python-to-path-on-windows-11-2/).
3. **Активируйте окружение** с помощью команды:
*   на macOS и Linux:
```
source venv/bin/activate
```
*   на Windows:
```
venv\Scripts\activate
```
*Или используйте `poetry shell` для активации виртуального окружения (доступно только при установленном плагине `poetry-plugin-shell`).*
4. **Установите все зависимости проекта** (указанные в файле `requirements.txt`) командой:
```
pip install -r requirements.txt
```
Также можно установить линтеры на выбор, используя Poetry с помощью команды:
```
poetry add --group lint <линтер>
```
Замените <линтер> на имя нужного линтера, например `flake8` или `mypy`, и они будут указаны в pyproject.toml. 
Если же использовать команду:
```
poetry add <линтер>
```
Тогда линтеры будут установлены для всего PyCharm

## -----------------------Тестирование------------------------

### Цель тестирования:
1. Тесты позволяют убедиться, что код работает так, как ожидалось, и выполняет все свои функции без ошибок.


2. Автоматизированные тесты предоставляют инструмент безопасности, позволяя разработчикам вносить изменения в 
   код без страха случайно что-то сломать.


3. Тесты ускоряют разработку за счет снижения количества времени, затрачиваемого на отладку и исправление ошибок в 
   будущем. Тесты также делают изменение и обновление кода более безопасными и предсказуемыми.


4. Регулярное тестирование помогает гарантировать, что изменения в одной части системы не нарушают функциональности в 
   других частях.


### Используемые инструменты: 
Для тестирования проекта используется библиотека **pytest**.
Все основные функции из модулей `masks.py`, `widget.py`, `processing.py` и `generators.py` покрыты тестами.

Тесты находятся в папке `tests/`:
- `test_masks.py` — тесты маскировки номера карты и счёта;
- `test_widget.py` — тесты маскировки по типу (карта/счёт) и преобразования даты;
- `test_processing.py` — тесты фильтрации по статусу и сортировки по дате.
- `generators.py` - тесты: фильтрации транзакций по заданной валюте; возвращения корректных описаний для транзакций;
                           генерации правильных номеров карт в заданном диапазоне.


### Покрытие тестами:

Все функции, в трех проверяемых модулях, покрыты тестами не менее чем на 80%,
что позволяет уверенно говорить о его надежности.

### Отчет о покрытии

HTML-отчет о покрытии тестами находиться в папке htmlcov/.
Чтобы сгенерировать отчет заново, запустите в терминале команду 
```
pytest --cov=src --cov-report=html
```

### Запуск тестов
```bash
pytest
```

## Список всех тестов:

### Модуль masks

#### Функция get_mask_card_number проверяется в:
**Тест 001:** Тестирование правильности маскирования номера карты.

**Тест 002:** Проверка функции на превращение номера карты типа int в тип str.

**Тест 003:** Проверка работы функции на различных входных форматах номеров карт, включая граничные случаи.

**Тест 004:** Проверка работы функции с нестандартной длиной номера карты.

**Тест 005:** Проверка, что функция корректно обрабатывает входные строки, где отсутствует номер карты.  

**Тест 006:** Проверка на то, что функция очищает номер карты от пробелов и дефисов.

**Тест 007:** Проверка на то, что функция не принимает номера карт состоящие из одинаковых цифр (залипание клавиши).
   

#### Функция get_mask_account проверяется в:
**Тест 101:** Тестирование правильности маскирования номера карты.

**Тест 102:** Проверка функции на превращение номера счета типа int в тип str.

**Тест 103:** Проверка работы функции на различных входных форматах номеров счетов, включая граничные случаи.

**Тест 104:** Проверка работы функции с нестандартной длиной номера счета.

**Тест 105:** Проверка, что функция корректно обрабатывает входные строки, где отсутствует номер счета.

**Тест 106:** Проверка номера счета c повторяющейся цифрой, например "00000000000000000000" (залипание клавиши).

### Модуль widget

#### Функция mask_account_card проверяется в:
**Тест 001:** Тестирование правильности маскирования номера счета и номера карты (параметризован разными типами карт и счетов).

**Тест 002:** Проверка работы функции с некорректным форматом номера карты или счета (неверная длина, неизвестный логотип, отсутствие цифр и т.д.).

**Тест 003:** Проверка, что функция корректно обрабатывает `None` вместо валидной строки.

#### Функция get_date проверяется в:
**Тест 101:** Тестирование правильности конвертации времени из международного стандарта (ISO 8601) в обычный формат `ДД.ММ.ГГГГ`.

**Тест 102:** Проверка работы функции с граничными значениями дат (начало и конец дня, 29 февраля).

**Тест 103:** Проверка функции на вход некорректных данных (не ISO-формат, несуществующие месяц/день/час/минуты/секунды, отрицательное время).

**Тест 104:** Проверка, что функция корректно обрабатывает пустую строку или `None`.

### Модуль processing

#### Функция filter_by_state проверяется в:
**Тест 001:** Тестирование правильности фильтрации списка словарей по заданному статусу `state` (на примере `'CANCELED'`).

**Тест 002:** Проверка работы функции без передачи аргумента `state` — используется значение по умолчанию `'EXECUTED'`.

**Тест 003:** Проверка, что при передаче пустого списка генерируется исключение `ValueError`.

**Тест 004:** Проверка, что при отсутствии ключа `state` в словарях функция возвращает пустой список.

**Тест 005:** Параметризованный тест с различными значениями статуса (`active`, `inactive`, `pending`), отсутствующими в исходных данных.

#### Функция sort_by_date проверяется в:
**Тест 101:** Тестирование сортировки списка словарей по датам в порядке убывания (по умолчанию).

**Тест 102:** Тестирование сортировки по датам в порядке возрастания (`descending=False`).

**Тест 103:** Проверка корректности сортировки при одинаковых датах (сохраняется стабильный порядок по времени).

**Тест 104:** Проверка работы функции с некорректными или нестандартными форматами дат (ожидается `ValueError`).

### Модуль generators

#### Функция filter_by_currency проверяется в:
**Тест 001:** Проверяет, что функция корректно фильтрует транзакции по заданной валюте.

**Тест 002:** Проверяет, что функция правильно обрабатывает случаи, когда транзакции в заданной валюте отсутствуют.

**Тест 003:** Проверяет, что генератор не завершается ошибкой при обработке пустого списка или списка 
              без соответствующих валютных операций.

#### Функция transaction_descriptions проверяется в:
**Тест 101:** Проверяет, что функция возвращает корректные описания для каждой транзакции.

**Тест 102:** Проверяет работу функции с различным количеством входных транзакций, включая пустой список.

#### Функция card_number_generator проверяется в:
**Тест 201:** Проверяет, что генератор выдает правильные номера карт в заданном диапазоне. 

**Тест 202:** Проверяет корректность форматирования номеров карт

**Тест 203:** Проверяет, что генератор корректно обрабатывает крайние значения диапазона и 
              правильно завершает генерацию.

**Тест 204:** Проверяет, что генератор корректно обрабатывает крайние значения диапазона.

**Тест 205:** Проверяет, когда начальное диапазона равно конечному.

**Тест 206:** Проверяет генерацию в том случае когда начальное значение равно нулю.

**Тест 207:** Проверяет правильность форматирования номера карты если конечное значение больше четырех цифр.

**Тест 208:** Проверяет что функция выбрасывает исключение в случае если значение диапазона отрицательное.
